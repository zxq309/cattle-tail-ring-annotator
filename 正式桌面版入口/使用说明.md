# 牛尾环九轴视频标注工具（桌面正式版 v7）

## 启动与基本流程

日常只双击 `正式桌面版入口/【双击启动】牛尾环标注工具.bat`；出现问题时使用调试启动批处理。

1. 打开真实九轴 JSON，再打开对应视频。
2. 文件名没有可靠时间时，先在“未钉住（校准模式）”中分别调整九轴和视频，再点击“钉住 当前帧=播放头”。
3. 一个文件夹只对应一头戴环牛。标注员只完整观看一遍，同时记录身体行为、尾部动作和客观事件。
4. 完成文件夹后填写真实 `cow_id`，保存工程；需要训练数据时再导出训练样本。

同一个长时段九轴 JSON 对应多个分段视频时，完成当前视频后直接打开下一段。工具会冻结切换过程中的联动回调，保留九轴播放头和曲线视窗，并把新视频的 0 秒续接到当前九轴位置。原来已钉住则切换后继续联动；原来未钉住则继续保持校准模式。

同一段视频跨越两个九轴 JSON 时，先保存当前工程，再打开下一份 JSON。新 JSON 从 0 秒开始，视频保留切换前的当前帧，程序把“新 JSON 0 秒”映射到该视频帧。注意：确认切换 JSON 会清空当前内存中的事件并开始新数据任务，因此切换前必须先保存当前工程和所需导出文件。

原视频和原 JSON 始终只读，所有时间都来自真实视频/JSON样本，不使用演示时间。

## 紧凑界面布局

- 主工作区左侧保留完整九轴波形，右侧扩大视频有效画面；中间分隔条可调整两侧宽度。
- 曲线的活动跳转、显示全程、时间尺度和播放头统一放在波形底部的一条导航栏，不再占用额外空行。
- 视频播放、逐帧、倍速、静音、音量和画面时间合并在同一条控制栏。
- 视频区域默认只显示常用的“钉住”按钮和当前对齐状态。角标时间、微调和 FFmpeg 维护位于“校准设置”，需要时展开。
- 标签与事件编辑区保持紧凑固定高度；标签选择、证据来源和备注集中排列，事件操作位于表格上方。
- 主工具栏只保留打开、载入和保存等高频操作；三种导出与标注对比集中在“导出与工具”菜单中，功能和快捷键不变。
- 模型预测、区间调整、标签/时间修改、确认复核和模型设置集中在顶部“模型辅助”下拉菜单中，不再单独占用第二行工具栏。

## 视频与九轴对齐及双向联动

- “钉住 当前帧=播放头”现在是开关。黄色按钮表示未钉住，绿色“✓ 已钉住（点击解除）”表示已钉住。
- 首次打开没有可靠时间信息的视频时，状态显示“未钉住（校准模式）”。此时拖动九轴只移动九轴，拖动、播放或逐帧操作视频只移动视频，方便人工找到代表同一真实时刻的两个位置。
- 校准模式下，微调按钮只移动视频：`+` 使视频向前，`-` 使视频向后，不改动九轴位置和正式时间映射。
- 两个位置确认后点击“钉住 当前帧=播放头”。程序按 `视频起点记录时刻 = JSON 起始记录时刻 + 九轴位置 - 视频位置` 建立映射，并立即进入双向联动。
- 视频拖动定位仍在等待播放器确认时，程序不会提前钉住；待画面到位后再次点击“钉住”。
- 文件名对齐、画面角标对齐、人工钉住、已钉住状态下的人工微调、分段续接、JSON 续接，以及载入工程中保存的有效对齐，都会使用同一套联动映射。
- 双向联动后，无论播放还是暂停：拖动九轴时间轴会同步定位视频；拖动视频进度条会同步更新九轴播放头。拖动只改变当前位置，不会重新计算或破坏已经保存的对齐关系。
- 已钉住时，微调按钮调整正式映射：`+0.1s/+1s/+10s` 使视频向前，`-0.1s/-1s/-10s` 使视频向后，调整后仍保持双向联动。
- 需要人工修正时，点击绿色“已钉住”按钮解除钉住。程序会暂停视频并保留当前两条时间轴位置；调整完成后重新点击钉住，映射以新的两个当前位置重新计算。
- 如果存在尚未结束的区间标注，程序会阻止解除钉住。请先结束该区间或按 `Esc` 取消，再进入校准模式。
- 未钉住时禁止创建新标注，也禁止正式导出；已有事件仍可查看和编辑。重新钉住后，标签和导出恢复正常。
- “零偏移待校准”不是可靠对齐，不能直接视为已经钉住；完成钉住、画面角标或其他有效校准后再开始正式标注。

## 播放与进度显示

- 视频标题栏右侧增加“⛶ 全屏”按钮；也可双击视频或按 `F11` 进入视频专用全屏。全屏只放大画面，不改变播放位置、倍速、静音状态或视频—九轴对齐关系。
- 全屏时按 `Esc`、`F11` 或双击画面退出；按 `Space` 播放/暂停，按 `←` / `→` 逐帧查看细节。右上角始终保留“退出全屏”按钮。
- 普通暂停后再次播放会直接从播放器当前帧继续，不再对同一位置重新发送定位请求，因此不会再因为程序反复回拉而循环当前位置附近的几帧。
- 拖动九轴或视频进度条、人工微调、重新钉住、切换视频/JSON和结束后重播仍会执行必要定位；这些操作不受“继续播放不重复定位”规则影响。
- 一个定位请求只发送一次。播放器每 400 ms 的定位看门狗现在只检查是否到位或是否超时，不再重复发送相同的 `set_time`。
- 每次拖动定位都有独立的“定位屏障”。定位前的旧视频时间、初始化0秒和上一轮定位时间不会再更新视频进度或九轴播放头。
- 暂停状态下先确认目标位置；开始播放时会在播放器进入可定位状态后再应用一次该目标。只有目标附近出现继续向前的真实解码时间，程序才解除屏障并恢复时间轴推进。
- 定位确认期间连续时钟暂停，避免界面已经前进而画面仍在旧位置。如果8秒内仍不能确认，程序取消本轮屏障并显示播放器实际位置。
- 播放期间，视频时间、视频进度条和已钉住的九轴播放头按照单调时钟每约 30 ms 连续推进；VLC 返回的稀疏时间只用于小幅校准，不会直接把界面时间拉到新值。
- 校准修正限制在当前播放速度的 ±12% 以内，所以时间轴会逐渐消除小误差，不会突然前跳或后跳。
- 已钉住播放时，暂停会冻结最后的连续确认位置，不再用滞后的VLC公开时间把视频和九轴拉回；未钉住校准、显式拖动、数据源切换、重新钉住和播放结束仍使用各自的实际播放器位置。
- 该逻辑适用于 1×、4×和10×。倍速越高，每次约 30 ms 刷新所对应的媒体时间步长越大，例如10×时通常约为300 ms，这是正常倍速换算，不是跳帧定位。
- 本修复直接播放原视频，不会自动调用“FFmpeg诊断/无损封装修复”，也不会生成MKV缓存；该按钮仅保留为严重损坏文件的人工备用工具。

## 异常录像时长自动校正

- 海康录像虽然使用 `.mp4` 文件名，内部可能实际是 MPEG-PS；不同播放器显示的总时长不一定可信。
- 首次打开此类录像时，工具会在后台只读校验视频包时间戳。此操作不会修改、转码或重新封装原视频。
- 检测到数小时级异常时间戳空洞后，工具会自动改用连续时间轴；总时长、当前视频位置、视频进度条、九轴钉住和标注时间会同时校正。
- 时间戳跳变后的损坏孤立尾段不足5秒时不会进入可标注时间轴，防止拖入该区域造成播放器异常。
- 状态栏出现“检测到视频时间戳异常”表示自动保护已经生效，不需要点击“FFmpeg诊断/无损封装修复”。
- 校验结果保存在工具系统缓存中；同一文件再次打开会直接使用缓存。视频文件被修改或替换后会自动重新校验。
- 若提示“视频时间轴校验失败”，工具会暂时使用播放器报告的原始时长。此时不要依据明显异常的数小时进度进行标注，应先确认 FFprobe 可用或使用人工备用修复功能。

## 切换视频与切换 JSON

### 当前 JSON 未结束，切换下一段视频

1. 在当前视频末段把九轴保持在下一段应续接的位置。
2. 直接打开下一段视频。
3. 切换期间不要重复点击播放或拖动；界面会显示时间轴冻结。
4. 新视频初始化完成后，九轴播放头和曲线视窗保持不变，新视频从 0 秒开始。
5. 检查画面是否连续；如有缺帧或录像间隔，解除钉住，独立调整后重新钉住。

### 当前视频未结束，切换下一份 JSON

1. 先保存当前工程；确认需要的导出文件已经生成。
2. 记住当前视频画面无需人工记录，程序会自动保存该视频位置。
3. 打开下一份 JSON，并确认清空当前数据任务中的事件。
4. 新 JSON 播放头从 0 秒开始，视频仍停在切换前的画面。
5. 原来已钉住则继续双向联动；原来未钉住则继续校准模式。

如果文件对话框被取消，或新数据在打开阶段失败，程序会恢复切换前的播放头、曲线视窗、对齐方式、钉住状态和原播放状态。

## 标注协议与工程格式

- 当前标注协议：`v4`。
- 当前桌面程序版本：v7。
- 工程 JSON 格式：继续使用 v4。三者是不同概念；载入旧工程时保留工程原有的协议字段，新打开 JSON 创建的任务使用 v4。
- 工程会保存当前是否钉住，以及未钉住时九轴和视频各自的位置。重新载入后会恢复原模式：已钉住工程恢复双向联动，未钉住工程恢复校准位置。
- 这些状态是 v4 工程中的可选字段，不改变工程版本；旧工程没有这些字段时，程序会根据原有对齐方式推断状态。
- 工程保存每条事实的开始、结束或点时间，并写入与自身边界一致的 `reviewed_range`、JSON 样本位置、可选备注、证据来源、标注员、协议和 `cow_id`。
- 工具只记录人工已经确认可靠的事件，不再提供置信度等级和牛尾可见性字段；无法可靠判断的事件不打标。

## 标注结束位置与事件时间

- 结束一次区间标注后，视频和九轴播放头继续停留在标注结束位置，不会因为程序自动选中新事件而回到开始位置。
- 事件表的“开始记录时间”和“结束记录时间”显示传感器实际记录时间，格式为 `YYYY-MM-DD HH:MM:SS.mmm`。
- “时长”显示该事件持续时间；点事件的结束位置显示“点”。
- 工程内部仍使用相对于九轴 JSON 开头的 `t0/t1` 毫秒值保存事件，保证样本定位、视频同步和训练导出准确。
- 用户手动点击事件表中的事件行时，播放头仍会跳转到该事件开始位置，方便复核。
- 模型预测标注可在导入前通过“修改选中建议”调整。导入后在事件表选择预测事件，工具会自动把该区间缩放到合适视野，并以半透明色带覆盖在全部真实九轴波形上。
- 在波形区直接拖动色带左右两侧的竖线即可调整开始或结束边界；鼠标靠近边界时会显示水平调整光标。
- `Ctrl+E`、“调整预测区间”和双击预测事件都会重新聚焦该区间。“修改标签/时间…”保留输入框方式，用于更换标签或输入精确数值。
- 波形拖动会吸附到真实九轴样本时间；发生身体行为重叠或同类标注高度重复时会撤回本次拖动。所有有效编辑都会保留原始模型标签、原始时间和调整历史，并支持撤销/重做。

## 起卧过程和排泄事件的边界

- 起立过程：从牛开始主动收腿、抬起躯干，到四肢完全支撑并稳定站立。
- 卧倒过程：从牛开始屈曲四肢、降低躯干，到身体完全着地并稳定躺卧。
- 排尿：从尿流清楚出现到尿流结束。
- 排便：从明确排便动作或粪便出现到排出结束。
- 四项都直接保存为独立区间，不再使用“排泄子类型”或“爬跨字段”。无法可靠判断时不打标，不使用“未知”标签代替。

## 努责和分娩节点

- 努责首次出现：首次出现明确、节律性的腹部用力，按首次清晰可确认帧记录为点事件。
- 努责区间：每段明确努责从腹部用力开始到该段用力结束，可与躺卧、站立、抬尾等标签重叠。
- 胎膜囊（水囊）首次可见：确认胎膜囊在阴门外连续可见至少1秒后，将时间回标到首次出现帧。
- 胎儿首个部位首次可见：任一胎儿部位首次在阴门外清晰可见；在备注中记录前肢、后肢、头部、尾部或未知。
- 犊牛完全娩出：最后一个身体部位完全越过阴门；脐带是否断裂不影响判定，该点作为核心 T0。
- 胎膜完全排出：胎膜完全脱离母体、不再悬挂于阴门；在备注中记录完全、部分或无法确认。

## 标注原则、保存和导出

- 只标记人工确认可靠的事件，备注为可选项。
- “导出 CSV”和“导出聚合 CSV”保留普通事件导出能力，不要求先填写 `cow_id`。
- “导出训练样本”按真实 JSON 样本时间生成多列数据，必须先填写 `cow_id`；`reviewed_any` 用于区分被事件覆盖的样本，工具不依据牛尾可见性推断负样本。
- 训练样本按15个独立标签生成 multi-hot 列；点事件对齐到最近的真实 JSON 样本。排尿和排便各有自己的列，不再生成旧 `EXCRETION/MOUNT` 子类型列。
- 有视频时必须处于已钉住状态才能导出。出现“视频与九轴当前未钉住”时，先完成校准并重新钉住；这是防止错误时间映射进入标注结果的正常拦截。
- 工程保存、载入、拖动、添加、删除和备注修改支持现有的原子保存及撤销/重做机制。

## 其他快捷键

- `Space`：播放/暂停；`[` / `]`：前一帧/后一帧。
- 视频播放到结尾后，再按播放会从当前视频开头重播；也可以先拖动右侧视频进度条，再从所选位置播放。重播只改变播放位置，不会修改既有视频—九轴对齐关系。
- `←` / `→`：播放头前后 100 ms；`F`：显示全程；`N` / `P`：跳转活动。
- `Ctrl+S`：保存工程；`Ctrl+Z`、`Ctrl+Y`：撤销/重做。
- `Ctrl+E`：在真实九轴波形上聚焦并调整事件表中选中的模型预测区间。
- `Delete` / `Backspace`：删除选中事件；`Esc`：取消待闭合区间。
- 时间尺度：1、2、3、4、5、10 分钟及全部。
