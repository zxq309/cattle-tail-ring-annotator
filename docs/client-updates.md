# 客户端更新（3.2.1 修订，2026-09-09）

## 客户怎么用

本修订版起，必须先完成启动更新检查，才构造标注/历史窗口和打开工程。发现新版就自动下载、校验并安装，成功后重新打开；客户不能跳过已发现的新版进入旧版标注。检查或更新失败时只提供重试和退出，网络不可用时也不会绕过启动检查。启动规则不受此前关闭自动检查、自动下载或已读提醒设置影响。

只推荐所选通道最新版，跳过中间版本。下载前、完成后及安装前重新检查，过时包不进入待安装状态。正常使用期间仍可在「帮助 → 关于 → 版本与更新」查看，后台检查不强退正在标注的工程；下一次启动执行上述规则。

本次按用户要求继续使用 3.2.1；已装早前 3.2.1 的用户需手动下载修订包一次。之后发布更高版本即可自动强制升级。原位置自动更新仅支持注册安装版；源码和便携副本在更新提示中打开安装包目录后手动安装，不覆盖开发目录。

更新在原安装目录旁的唯一临时目录解包，逐文件校验并导入测试私有运行库，再交换目录、重新注册快捷方式和卸载入口，最后重开。解包/校验失败不替换旧版；目录交换或注册失败恢复旧目录。校验期间不覆盖正在运行的 DLL。会额外需要约一个完整安装目录的磁盘空间，另有下载包缓存；原始录像不复制。

软件安装目录内若有未知文件（包括用户另放的标签、原始九轴、模型包），会先提示移到数据工程，绝不吞掉它们。既有工程根目录、标注、QSettings 配置及校准都不移动。便携/源码副本可以检查和下载安装包，但不接受原位置覆盖，以免破坏开发内容。

旧 r3/r2/rc1 客户端没有这段代码，必须手动升级一次；不能靠上传新 EXE 给旧客户端“隔空补上”更新器。此次引导安装仍使用新的空软件目录，之后的安装版更新由客户端管理原位置替换。

## 维护者每次修 bug 后

1. 递增 cowmata_tailring/__init__.py 中可比较的版本号，更新构建号、CHANGELOG 与中英 README。不要只覆盖同版本 EXE；例：3.1.0 → 3.1.1。
2. 全量测试、打包离线载荷。安装器版本例如 3.1.1，文件名必须为 COWMATA-Annotator-3.1.1-Setup.exe。
3. scripts/build_installer.py 会同时生成 EXE、.exe.sha256、cowmata-update.json。清单含产品/协议/版本、安装器大小与 SHA-256、解包清单 SHA-256、所需空间。
4. 在固定仓库 zxq309/cattle-tail-ring-annotator 创建匹配 tag 的草稿 Release，上传这三个文件；核对附件齐全和 GitHub 的 digest，再发布草稿。预览版勾选 prerelease。客户端不读草稿，也不从任意外链运行 EXE。
5. 从一个已安装的上一更新版实际验证检查、下载、保存退出和原位置更新后，再作为正式交付。不能仅凭单元测试宣布 GitHub 端到端已发布成功。

大型 EXE 仍是 Release 附件，不进 Git 源码历史。生成的清单也必须作为 Release 附件，单独上传 EXE 不足以安全自动更新。客户端不包含维护者令牌。

## 安全与边界

本版使用固定仓库 HTTPS、GitHub 资产 digest 与逐文件清单做完整性验证，**没有商业 Authenticode 签名，也没有维护者私钥签名**。这不等于代码签名，不防御仓库维护账号被攻破，也不绕过 SmartScreen。不要关闭安全软件。GitHub 老附件没有 digest、清单不一致或文件被撤回时，客户端拒绝自动安装并保留当前版本。

更新下载和独立运行库位于当前用户 LocalAppData/COWMATA Annotator/updates；对话框“清除下载”只清本版本安装包/分片。失败的事务保留 result.json/error.json 和必要的阶段目录，供维护者核对；不要用递归强删修复。突发断电/外部进程占用导致恢复自身失败时，需按日志恢复目录，不宣称能保证任意断电点自动恢复。

本地测试与公开发布是两件事。本版本在没有实际发布验证之前，不宣称已有客户已自动升级。
